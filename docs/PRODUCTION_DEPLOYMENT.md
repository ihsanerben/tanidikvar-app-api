# Production deployment

This repository deploys the API to a Render Free web service. The React SPA is
deployed from the neighbouring web repository to Vercel, and PostgreSQL is
hosted by Neon. The local Docker workflow remains unchanged: it uses Mailpit
and `MAIL_PROVIDER=smtp`.

## Required production configuration

Create a Render Blueprint from `render.yaml`. Before its first deploy, set the
following secret values in Render. Do not put any of them in Git, `.env.example`
or a Vercel environment variable.

| Variable | Source / value |
| --- | --- |
| `DB_URL` | Neon pooled JDBC URL (`jdbc:postgresql://…?sslmode=require`) |
| `DB_USERNAME` | Neon connection user |
| `DB_PASSWORD` | Neon connection password |
| `CORS_ALLOWED_ORIGIN` | Canonical Vercel production origin, without a trailing slash |
| `FRONTEND_URL` | Same canonical Vercel production origin, without a trailing slash |
| `MAIL_FROM` | Verified Resend sender, e.g. `TanıdıkVar <noreply@example.com>` |
| `RESEND_API_KEY` | Resend API key with mail-send permission |
| `PILOT_MODE` | `true` for the free pilot; keeps persistent-file features closed |

`JWT_SECRET` is generated by Render from the Blueprint and must remain stable
after the first deploy. Rotating it invalidates every active session.

The application reads Render's `PORT`, serves `/api/health` as its health
check, enables secure cookies, and runs Flyway migrations at startup. Render
Free can sleep after inactivity, so the first request after sleep can be slow.

## Resend in production, Mailpit locally

`MAIL_PROVIDER=smtp` is the default and uses the existing Spring SMTP settings.
Local Docker continues to route it to Mailpit. Production sets
`MAIL_PROVIDER=resend`; the backend then sends transactional e-mail through
Resend's HTTPS API. Render Free blocks SMTP ports, so do not set Gmail SMTP
credentials in Render.

Resend requires a verified sending domain to deliver production e-mail to
users. Add the DNS records Resend provides before enabling registrations.

## Vercel API proxy

The browser must call the API through the Vercel origin, not directly through
the Render origin. This preserves the existing HttpOnly `SameSite=Lax` session
cookies. After Render creates the API URL, add it as the `destination` in the
web repository's `vercel.json` API rewrite, then set
`VITE_API_BASE_URL=/` in Vercel Production environment variables.

The final rewrite order is:

1. `/api/:path*` → `https://<render-api-host>/:path*`
2. `/(.*)` → `/index.html`

Do not cache `/api` responses at Vercel: they can contain user-specific data or
Set-Cookie headers.

## Storage blocker

Render Free has an ephemeral filesystem. With `PILOT_MODE=true`, the API
rejects avatar uploads and Admin application document uploads, and profile
completion does not require an avatar. The web build likewise hides both
actions. This prevents metadata that points to files which Render can lose.

Do not switch `PILOT_MODE` off until a private object-storage provider is
selected and the current local-disk storage adapter is replaced. Neon persists
only metadata, not file bytes.
